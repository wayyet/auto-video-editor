| 实验 | 结果 |

| 资源包格式对比 | 互动立体包 config = `TextStyle version 13.9.0`;黄字橙光包 = `InfoSticker version 6.3.0`——均超出便携版 5.9.0.11632 的支持范围(与「螺旋上升」动画包新格式加载失败同款) |

### 3.4 三条剪映 UI 行为新知(实验副产品,已固化到认知)

1. **面板 ⊘ 语义**:花字面板只对「当前可见列表中的花字」做高亮;已应用的花字若不在列表中(如互动立体),回落显示 ⊘。面板读 refs 状态(点击应用后高亮即时移动),但列表外资源无法高亮——**⊘ ≠ 未应用,判定以 draft_content.json 为准**。
2. **UI 应用 = 替换语义**:点击新花字会把该段 refs 里的旧花字替换掉(×2 形态),旧条目留桶成孤儿。
3. **UI 保存会 GC 孤儿 text_effect 条目**:被替换/解绑的花字条目在下次 UI 保存时被自动清除(实验中两个孤儿条目均被 GC)——流水线的清理与 QA 孤立告警是双保险之外,剪映自己也会收。

### 3.5 verified 语义修订(重要教训)

11-18 给「互动立体」授 `verified=true` 时依据的是**应用状态实证**(条目写入+资源下载+结构存活),**渲染自始未经目检**——本实验证明「GUI 应用成功」≠「渲染成功」。今后收割(P8)/验证的 verified 授予必须以**渲染目检通过**为前提。
