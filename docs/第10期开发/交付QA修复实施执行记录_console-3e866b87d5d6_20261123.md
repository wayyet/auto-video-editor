## 1. 阶段 0 取证定案（全部完成）

证据与结论详见 `outputs/console-3e866b87d5d6/stage0_evidence/EVIDENCE_SUMMARY.md`（checkpoint 经 Docker `edb-postgres16` + `graph.aget_state` 实取，两份草稿 sidecar/审计/快照已备份至同目录）。要点：

1. **层 1（首编失败）实锤**：zh/en 首编均为 `compile_spec` 抛
   `SegmentOverlap`（zh 区间 `[16899999, 34999999]`、en `[0, 17214000]`）。
   根因 = zh 两条 `voiceover_zh` 段区间**重叠 314ms**（`0-17214000` 与
   `16899999-34999999`），提取器原样吸收进 spec.audio_clips，编译器同轨铺段
   fail-closed。node_08 配音重铺/上游 TTS 槽位重叠是上游独立缺陷
   → **另案处理**（见 §5 遗留项）。
2. **层 2（repair 阻断）实锤**：zh spec `compile.last_result` =
   `failed_blocked_features`，blocked = `manual_text_track ["hook-title-seg-1"]`；
   en 因 hook 只挂视频段特效 ref（`video_effects` 桶放行）而编译成功。
3. **hook 被静默抹掉实锤**：en 编译成功后 `hook-effect-1` 被重建抹除。
4. **QA 终局类别成因**：SDK 链转正后 node_08 不再直接写草稿字幕（审计
   `changed_counts` 仅 `materials.speeds 7→9` = 配音重铺），字幕/转场落草稿
   完全依赖编译成功 → zh 编译从未成功 → 草稿全裸 → `subtitles_zh=failed;
   transitions=failed`。审查 R-01/R-02/R-03 的取证方法修正全部按计划执行
   （HTTP 快照仅作旁证、阶段化异常边界、审计缺失=有限置信度推断）。
