## 2. FireRed 参考样例导出(不含任何 API Key)

### 2.1 script_template_rec 输入输出

输入(节点 state):`user_request`(文案风格要求,空串允许)、`filter_include: Dict[str, List[str]]`(正向标签,维度 AND/同维 OR)、`filter_exclude: Dict[str, List[str]]`(排除标签)、`mode`(auto/skip/default,框架层消费,非 auto 直接不出候选)。

流程(`script_template_rec.py` b45011d):`ElementFilter(json_path=script_template_info_path)` 读模板元数据 → `StorylineRecall.build_vectorstore(library)` 按 `description` 字段建 FAISS 索引(本地模型 all-MiniLM-L6-v2,缺失回退 HuggingFace 远端模型)→ `query_top_n` 语义召回 Top 32 → 标签过滤 → 返回 `{"candidates": candidates[:3]}`,候选是 meta.json 条目整条 dict。

**明确不照搬**:`ElementFilter.filter()` 在过滤结果为空时会 `random.sample(self.library, min(10, len(library)))` 随机抽 10 个兜底——本项目必须确定性降级返回空候选(`no_match`),不许随机选不相关模板。

### 2.2 模板 meta.json schema

FireRed 仓库树**未提交**实际模板资源(`resource/script_templates` 目录存在但为空),meta.json 由 `scripts/llm_script_template_label.py` 离线生成:遍历模板 .txt → 计算 MD5 → LLM 生成 `description`(一句话 ≤30 字)与 `tags`(1~3 个,枚举 [Life, Food, Beauty, Entertainment, Travel, Tech, Business, Vehicle, Health, Family, Pets, Knowledge])→ 内容变化才重新标注。核心字段:`id / path / description / tags`。

本项目扩展 schema(阶段 1 落地):`schema_version / templates[{template_id, path, language, description, tags, content_sha256, version, enabled}]`,hash 升级为 SHA-256。

### 2.3 AI 转场 Provider 调用链样例(MiniMax Hailuo-02,来自 worktree 副本 `utils/ai_transition_client.py` L187-240)

```
BASE_URL  = https://api.minimaxi.com/v1
模型       = MiniMax-Hailuo-02(默认 768P)
认证       = Authorization: Bearer <api_key>(仅服务端环境变量,不进 state/日志)

提交   POST {BASE_URL}/video_generation
        payload = {model, prompt, first_frame_image, last_frame_image,
                   duration(默认 6 秒), resolution("768P"),
                   prompt_optimizer, aigc_watermark:false}
        → 响应取 task_id
轮询   GET  {BASE_URL}/query/video_generation?task_id=<id>
        间隔 15s;status=="Success" → 取 file_id;status=="Fail" → 抛错
取址   GET  {BASE_URL}/files/retrieve?file_id=<file_id>
        → 响应 file.download_url
下载   GET  download_url(stream)→ result_<task_id>.mp4
```

`first_frame_image` / `last_frame_image` 接受 base64 dataURL(本地文件无需公网图床)。

### 2.4 转场产物结构(FireRed `transition_info`)

```json
{"transition_0001": {"fps": 30.0, "path": ".../result_<task_id>.mp4",
                     "source_ref": {"duration_ms": 6000, "width": 768, "height": 1366}}}
```

duration_ms 由生成后实测(非提交参数);生成结果插入 group 的 `clip_ids` 作为独立片段,`plan_timeline_ai_transition` 按 `clip_id.startswith("transition_")` 识别并单游标累计时间线。FireRed **无结果级缓存**(qa 重试会重复付费)——本项目必须补缓存键。宽高比守卫:`MAX_ASPECT_RATIO_FACTOR = 1.1`,两侧比例差超阈值跳过该 pair。

## 6. 阶段 2 真机验收步骤(待操作员)

前置:剪映关闭;`MINIMAX_API_KEY` 已配置;明确知悉单次运行会产生 N−1(group 边界数)次 6 秒视频生成的第三方费用。

1. 环境变量:`STORYLINE_AI_TRANSITION_PROVIDER=minimax`、`STORYLINE_AI_TRANSITION_APPROVED=true`(或 state 注入 `ai_transition_approved=true`)。
2. 新建创建台任务跑通主线;检查 `outputs/<job>/storyline/ai_transition.json`:items 应含真实 `video_path` 且 `is_stub=false`;`ai_transitions/` 目录应有 mp4 且 ffprobe 可读。
3. `outputs/<job>/storyline/timeline_plan_ai.json`:转场 clip 应插在相邻 group 边界处,`options.enable_ai_transition=true`。
4. 剪映打开生成草稿:预览应能看到边界处过渡视频;交付 QA 报告无新增告警。
5. 触发一次 qa 重试场景:确认 ai_transition 重跑时命中缓存(日志无新的 Provider 提交,无重复扣费)。
6. 未配置 Key 或未批准时:artifact 应显式 `provider_unconfigured` / `awaiting_approval`,且 `ai_transitions/` 目录无任何生成文件。

设计偏差记录(均为等价或更优实现):
1. 拓扑接法:设计文档画的是 STR 与 web_topic 并行汇聚;实际 LangGraph 独立 `add_edge` 是"任一来源完成即触发",并行接法在 web_topic 关闭时会让 generate_script 每轮跑两次。改为 STR 上主链、条件路由挂其出口,语义等价。
2. 提示词:FireRed 用视觉 LLM;本项目后端为纯文本,按用户决策改文本 LLM 生成(确定性兜底)。
3. 转场缓存键的"素材 hash":大视频整文件 sha256 每轮代价过高,落为 路径+大小+mtime 指纹(任务内确定性、文件变化即失效;缓存本就按 job 隔离)。
4. FireRed `ElementFilter` 的随机抽样 fallback 未照搬(设计文档明令禁止),空结果确定性 `no_match`。
