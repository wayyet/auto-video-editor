## 1. 快进速度:语义定稿(智能保同步)

现有机制:每段播放速度 = 素材跨度 ÷ 段时长(全自动推导),唯一速度下限是慢放护栏 `STORYLINE_MIN_CLIP_SPEED=0.5`(`timeline_planner._apply_source_span_caps` / `node_07` Pass1 / `contract` 不变量 / `qa_gate` 复查四处共用)。配音开启时段时长按"配音刚好装满"分配;**段时长被压短 → node_08 重铺的配音顺延压到后续画面(音画错位)**;扩 source_span 则完全无此问题。据此定稿:

- `speed_multiplier = N > 1`:每段至少 N 倍速。
  - **第一优先**:同一素材内向后扩 `source_out` 到 `ceil(N×slot)`——段时长/时间戳/配音/总时长全不动(快进的本质:同样时间展示更多内容);上界 = 同素材内下一个 clip 的 `source_in`(绝不吞并别人已选区间)或素材 `duration_ms`。
  - **素材余量不足**:TTS(配音)段保原速并写 warning(绝不音画错位);非 TTS 段(BGM 节拍/等比模式)由 `_apply_source_span_caps` 抬高下限到 `max(0.5, N)` 压短兜底,成片短于目标时长属预期(不注水)。
- **默认 1.0 = 不启用,行为与旧版逐字节一致**。
- 用户下限**只在规划期生效**;contract(0.5)/qa_gate(0.5)/node_07 拉长护栏(0.5)全部不动——避免把规划器特意保留的配音段在下游重新压短。
