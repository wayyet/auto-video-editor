# 剪映整合分析：能否在现有方案上做到「更自动化」

> 结论先行 + 已落地的整合代码说明
> 日期：2026-06-14　承接《旅游视频AI自动剪辑实施方案》

---

## 一、一句话结论

**能，而且建议这么做——但要分清「更自动化」的两层含义。**

把 `luoluoluo22/jianying-editor-skill` 接到你现有的 pipeline 上，会让「**成片质量与特效的自动化程度**」大幅提升：转场、滤镜、花字片头、逐句打字机字幕、运镜关键帧、剪映云端曲库这些原来要手动或要额外写 Remotion 才能做的东西，现在能**按名字一句话自动套上**，而且产出的是**可以再手动微调的剪映草稿**，不再是一锤定音的 mp4。

代价是：**「无人值守」这一层反而下降了一点**。剪映的自动导出本质是「在真实桌面上模拟鼠标键盘」，导出时不能碰电脑、必须锁死在 5.9 版、且只能在装了剪映的 Windows 机器上跑——不像纯 ffmpeg 那样能在云端完全无头批量。

你这次明确「更看重成片质量/特效」，所以**推荐把剪映路线作为出精品片的新默认渲染层（路线 D）**，把原来的纯 ffmpeg 渲染降级为「快速预览 / 批量矩阵量产」的备选。两者共存，各司其职。

---

## 二、为什么剪映 skill 是「补齐短板」而不是「另起炉灶」

你原方案的流水线（路线 A，已在 `pipeline.py` 跑通）强在**前半段「理解与决策」**：
ffmpeg 切条、PySceneDetect 分镜、Claude 逐帧看画面打分、LLM 写文案定时间线、商用 TTS 配音。这部分**纯云端 API、无需 GPU**，是整套方案最有价值、也最难被现成工具替代的部分。

它弱在**后半段「装配与包装」**：ffmpeg 只能做裁切/拼接/压字幕/混音这些「硬」操作。要做电影级转场、花字标题、逐字弹出字幕、运镜，得自己写 Remotion + GSAP，工程量不小，效果也难追上剪映现成模板库。

剪映 skill 恰好补的就是这后半段。它的本质是**用代码去搭剪映的时间轴**（底层是 `pyJianYingDraft` 生成草稿工程文件），然后调一个 GUI 自动化脚本点「导出」。所以正确的组合不是二选一，而是**前段用你的 pipeline 当导演，后段用剪映 skill 当装配工**。

| 能力 | 纯 ffmpeg 路线（原路线 A） | 剪映 skill 路线（新路线 D） |
|---|---|---|
| 画面理解 / 选镜 / 文案 | ✅ Claude（保留） | ✅ Claude（保留，不变） |
| 镜头拼接 / 竖屏裁切 | ✅ | ✅（剪映里可智能构图，效果更好） |
| 转场（叠化/闪白/运镜转场） | ⚠️ 仅基础，难看 | ✅ 剪映自带库，一句话套 |
| 滤镜 / 画面特效 | ⚠️ 手写滤镜 | ✅ 按名字搜索套用 |
| 花字片头 / 标题动画 | ❌ 需另写 Remotion | ✅ 原生文本动画（复古打字机等） |
| 逐句字幕 + 入场动画 | ⚠️ ASS 静态字幕 | ✅ 逐句对齐 + 打字机/弹出动画 |
| BGM 来源 | 自备免版权曲库 | ✅ 还能直接用剪映云端曲库 |
| 产物可否再手动微调 | ❌ 只有成品 mp4 | ✅ 草稿可在剪映里改完再导出 |
| AI 语义配画面（B-roll） | ❌ | ✅ v1.4 三模态语义匹配 |
| 完全无头 / 云端批量 | ✅ 强项 | ❌ 导出要占用真实桌面 |

## 三、整合后的架构（路线 D）

核心变化只有一处：**把原架构第 ⑥ 步「ffmpeg 渲染合成」替换成「产出交接文件 → 剪映装配 → 自动导出」**，前五步原封不动。

```
你的输入：视频 + 主题 + 提示词
        │
   ┌────┴───────── 第 1 段：理解与决策（无头，云端 API，无需 GPU）──────────┐
   │ ① 预处理  ffmpeg + PySceneDetect 切分/抽帧                              │
   │ ② 画面理解 Claude 逐镜头打标评分                                        │
   │ ③ 脚本决策 LLM → 解说文案 + 剪辑时间线                                   │
   │ ④ 配音字幕 商用 TTS → 旁白 + 逐句时间轴                                  │
   │ ⑤ 选 BGM                                                               │
   │ ⑥a 裁出镜头片段 + 写 edit_spec.json  ← 新增「交接层」                    │
   └───────────────────────────────┬───────────────────────────────────────┘
                                    │  （通过共享文件夹 kuaishou 衔接）
   ┌────────────────── 第 2 段：装配与导出（Windows + 剪映 5.9）─────────────┐
   │ ⑥b jy_build.py 读 edit_spec.json：                                      │
   │     铺镜头 → 旁白 → BGM → 片头 → 逐句字幕 → 套转场/滤镜 → 存草稿          │
   │ ⑦  （可选）人工进剪映微调                                                │
   │ ⑧  auto_exporter 自动导出 1080×1920 mp4                                 │
   └─────────────────────────────────────────────────────────────────────────┘
                                    │
                            成片 mp4 → 快手发布
```

**最关键、也最容易踩的一点**：第 1 段和第 2 段在**两台不同的机器**上跑。

- 第 1 段是 Linux/云端逻辑（你的 `pipeline.py`），可以在 Cowork 这边由我直接跑；
- 第 2 段必须在**装了剪映的 Windows 本机**跑，因为要写剪映草稿目录、并驱动剪映 GUI 导出。

我已经把交接文件 `edit_spec.json` 里所有路径都改成**相对项目根目录**，所以「Linux 跑前段、Windows 跑后段」不会因为路径不同而失败。

## 四、分工：谁负责什么

| 环节 | 负责方 | 说明 |
|---|---|---|
| 看懂每个镜头拍了什么、好不好 | **Claude**（你的 pipeline） | 剪映 skill 不擅长，且这是核心价值 |
| 写解说文案、定镜头顺序与时长 | **Claude** | LLM 的活 |
| TTS 配音、逐句字幕断句对时 | **Claude / pipeline** | 已跑通；剪映也能做，但用你现成的更可控 |
| 套转场/滤镜/花字/字幕动画 | **剪映 skill** | 它的主场 |
| 竖屏构图、运镜关键帧 | **剪映 skill** | 比 ffmpeg 裁切好看 |
| 生成草稿、自动导出 mp4 | **剪映 skill** | `pyJianYingDraft` + GUI 自动化 |
| 人工最后微调（可选） | **你** | 草稿可改，这正是相比纯 ffmpeg 的最大灵活性 |

一句话：**AI 决定「剪什么、怎么讲」，剪映负责「搭好时间轴、做漂亮、点导出」。**

## 五、诚实的限制与取舍

1. **自动导出不是真无头**：它模拟鼠标键盘点剪映的导出按钮，导出过程中不能碰电脑，也无法在没有图形界面的服务器上跑。要无人值守批量量产，纯 ffmpeg 路线反而更合适。
2. **版本锁死 5.9**：你现在的 5.9.0.11632 正好可用，但**必须禁用剪映自动更新**，升到 6.0+ 自动导出就会被弹窗打断。
3. **只支持桌面版剪映**（Windows/Mac），手机剪映用不了。
4. **剪映自带的实时 AI 功能调不动**：智能抠像、美颜、剪映自己的语音识别字幕、「一键成片」这类需要剪映 GPU 实时处理的按钮，skill 没法触发——但这些我们本来就用 Claude + TTS 自己实现了，不冲突。
5. **转场/特效是 best-effort**：不同 skill 版本的方法名可能有差异。`jy_build.py` 对此做了容错（套不上不会报错，会打印清单让你用 `asset_search.py` 查名补上）；镜头/旁白/字幕/BGM/片头走的是已确认的稳定接口，不受影响。
6. **成本不变**：仍然是单条 < ¥1（视觉分析+文案 LLM、TTS 各家免费额度），剪映装配与导出是本地免费。

## 七、下一步（还差什么才能真出片）

1. **放素材**：往 `input/` 放 1~3 条视频（现在 `input/` 是空的，没素材跑不了真片）。
2. **填 TTS Key**：`config.yaml` 里火山引擎/阿里云/MiniMax 任一（首次配一次）。
3. **装 skill**：按 `RUNBOOK_剪映整合.md` 第 0 节，在本机装 jianying-editor 并禁用剪映自动更新。
4. **跑两段**：
   - 第 1 段（我可以在 Cowork 直接帮你跑）：`python pipeline.py -i input/xxx -t "主题" --render jianying`
   - 第 2 段（在你的 Windows 上）：`python jy_build.py --spec output/edit_spec.json`，满意后加 `--export`。

> 第 2 段需要在你的 Windows 桌面上操作剪映。如果你愿意，我可以用桌面控制能力**直接在你电脑上完成安装与首条出片的全过程**——你只要先放好素材、填好 TTS Key 即可。
