## 3. 与审查文档的偏差(2 项,均已记录理由)

### 7.2 A/B 实验定案:渲染失败在**剪映客户端**,不在写入层

现象:草稿层花字已应用,但剪映预览**素文本渲染**、花字面板对已应用字幕显示 ⊘。

computer-use 桌面自动化实验(基线快照 → 面板点击应用 → Ctrl+S → JSON diff):

1. **UI 应用形态与流水线写入完全同构**:26 字段逐字段一致(×2 复制、refs 替换语义一致);唯一字段差异 = `request_id`(UI 非空 `20261121…A33A8`,流水线空)。
2. **两个不同花字经 UI 手动应用(黄字橙光花字 effect_id 7506878563723840783、土酷红黄色花字 6896137859)同样不渲染** → `request_id` 不是渲染开关,**渲染失败在客户端加载/渲染环节**。
3. **资源包完整**(黄字橙光刚下载 8 文件齐、互动立体 5 文件齐),账号有 VIP 徽标 → 排除下载缺失与授权缺失。
4. **根因定案(与字幕动画「螺旋上升丢失」同款)**:便携版剪映 **5.9.0.11632(旧客户端)无法渲染服务端当前下发的花字资源格式**——互动立体包 config `TextStyle version 13.9.0`、黄字橙光包 `InfoSticker version 6.3.0`,均超旧客户端支持范围 → 加载失败静默 fallback 素文本。
5. **面板 ⊘ 语义澄清**:面板只对「当前列表中存在的花字」做高亮;互动立体不在面板当前可见列表 → 已应用的字幕回落显示 ⊘。面板高亮随 UI 应用移动 = 面板读 refs 状态,但列表外资源无法高亮。
6. **UI 保存会 GC 孤儿花字条目**:被替换/解绑的 text_effect 条目在下次 UI 保存时被自动清除(实验中黄字橙光、seg-1 原 78B2D069 孤儿均被 GC)——流水线的我方孤儿清理与 QA 孤立告警是双保险,但 UI 自己也会收。

### 7.3 结论与处置

- **写入实现无需修改**(结构=UI 同形;request_id 不补——实测非渲染开关,伪造追踪 id 有未知副作用);
- **阻塞项 = 剪映客户端版本**:升级剪映(≥资源格式兼容的版本)后重验渲染;便携版升级属操作员环境决策;
- 草稿实验残留:seg-1 现挂「土酷红黄色花字」(UI 应用,不渲染),seg-2~6 仍为流水线的互动立体;流水线重跑 node_10 会恢复 seg-1 的互动立体绑定并清理我方孤儿,UI 写入的土酷条目无标记不会被流水线清理(QA 孤立告警可见);
- 花字池收割(P8)与更多资源验证:**必须以「渲染目检通过」为 verified 授予前提**(本实验证明「GUI 应用成功」≠「渲染成功」——11-18 的互动立体 verified 实为应用状态实证,渲染自始未通过;verified 语义修订为含渲染目检)。
