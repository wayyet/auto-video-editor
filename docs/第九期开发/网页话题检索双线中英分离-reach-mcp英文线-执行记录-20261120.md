## 2. 关键实施事实(与审查文档的偏差及理由)

1. **传输层实现偏差(重要)**:审查文档 §5.2 建议 mcp SDK `streamablehttp_client`;实施时发现 **phase5 解耦门禁**(`scripts/assembly/phase5_e2e.py::case_decoupling`,集成测试 CI 必跑)规定全仓仅 `agent_gate/` 可引用 mcp SDK(第五期依赖约简的架构纪律)。**架构纪律优先**:reach_client 改为**裸 JSON-RPC over httpx**(三步握手 initialize → notifications/initialized → tools/call),零 mcp SDK 依赖、零 asyncio(同步 httpx);协议已对活容器实测(响应恒为 SSE 流,取最后一条 `data:` 行解析;session id 经 `Mcp-Session-Id` 头)。真机端到端复验:同一 request_hash、status=ok、10 条,与 SDK 路径行为完全一致。P1-05(SDK 版本迁移)问题随之消失。
2. **容器是 docker-compose 部署**(审查文档假设 docker run):工作目录 `C:\Users\wayyet\reach-mcp-docker`(原文件已备份为 `*.bak-20261120`)。重建经 compose 完成,未破坏用户部署形态。
2. **宿主代理 3067 仅绑 127.0.0.1**,容器经 host.docker.internal 不可达;**1088 绑 0.0.0.0 且为纯 SOCKS 端口**(HTTP 协议探测 000 失败)→ 容器代理走 `socks5h://host.docker.internal:1088`。reach 镜像内 httpx 缺 `socksio` → 本地 Dockerfile 叠加安装(`reach-mcp-local:socks`,base pin `ghcr.io/xyonium/reach-mcp@sha256:a584251da6d3d9d4872090ec024878ce2deea2a058488f777110ef109913befb`,server 版本实测 1.30.0)。
3. **web 源依赖 SearXNG**(审查 P0-02):部署 `searxng` 容器与 reach-mcp 同 compose 网络;`settings.yml` 显式放开 `format=json`(上游 web.py 实证用 JSON API)+ `outgoing.proxies: socks5h://host.docker.internal:1088`(SearXNG 出站也要过代理,bing/google 直连全超时实测)。**逐源实测**:web 20 条(SearXNG 内 3 条/sample)、youtube 3 条、reddit RSS 对代理出口 IP 返回 403 反爬页(190KB HTML)→ reddit 已知降级,由部分成功语义兜底,diagnostics 如实记录。
4. **端口 loopback 发布**(P0-07):`127.0.0.1:8765->8765`。
5. **英文消费者接线为两源屏障**(审查 §6.4 有界等待):`[node_14_make_covers, storyline_search_web_topic_en]→node_15` 与 `[fork_draft_for_english_branch, en]→node_16a`。**实施教训**:先写成两条独立普通边,LangGraph 语义下目标节点会**每条边各执行一次**(node_15/16a 在 en 完成后提前触发一次,黄金轨迹实测证伪)→ 改为列表屏障(AND-join)后 61 例集成测试全绿。屏障源均为每轮必跑节点,不踩 D10。
6. **`_last_wins` tombstone**(P0-04):`None` 不清值、`""` 清值,已加 reducer 单测;英文节点产物写失败时 State 置 `""` 并追加 `ARTIFACT_WRITE_FAILED` error_log。
7. **每轮必写产物**(P0-05):英文节点对 ok/cache_hit/no_results/failed/skipped 五态都覆盖写 `storyline/search_web_topic_en.json`,skip 也覆盖旧文件,UI 不会读到过期英文资料。
8. **request_hash 完备**(P0-06):`reach_request_provider` 串编码 sources(排序去重)/max_per_source/days/max_chars_per_item/adapter_version;max_results 与 query 由 `build_request_hash` 统一编码。参数变化测试锁定。
9. **MCP 返回解包**(P1-01):实测服务器 `structuredContent=None`,数据在文本 content 块 JSON 里 → 解包先 structuredContent 后文本 JSON;`isError=True` → TOOL_ERROR。
10. **源状态宽容**(P2-02):`sources_used` 原样保留(限长 50 条/字段截断),全部源 error → NETWORK_ERROR(不伪报 no_results);`source_summary` 限长 200 进产物与 UI。
11. **翻译参考注入**(§7):`reference` 为单次调用参数(Protocol/Mock/LLM/translate_segments 全链透传),不落共享客户端实例状态;`reference=None` 时 system/user prompt 与 v2 **逐字节一致**(单测比较全文);`TRANSLATION_PROMPT_VERSION` v2→v3,marker schema 2→3(+`reference_sha256`/`reference_sources`);空参考哈希=sha256("") 固定值。**存量 v2 marker 一次性失效重翻**(预期代价)。
12. **SOURCES 校验偏好**:只做格式校验(标识符字符集),不硬编码上游源名单 —— 上游会新增源,名单过期反而阻断;不可用源由 diagnostics 暴露(与审查 §5.3 "拒绝不在允许源名单内的名称"的字面要求不同,已在代码注释说明理由)。
13. **SCHEMA_VERSION 11→12**(monitoring/workflow_graph.py):新增节点=拓扑变更,布局缓存失效;集成断言同步。
14. **并行会话协同**:阶段 0 发现 translate 链 7 文件有并行会话 WIP(翻译形状漂移审查执行中);调整实施顺序(B/C/D/F 先行),阶段 E 开工前确认其已提交(`88a8327`),全程精确 git add,未动并行文件。
