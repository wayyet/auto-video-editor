## 1. 背景与目标

审查文档给出了双线中英分离的修订设计，其中英文线原采用 Xpoz（TikTok/X/Reddit/Instagram 商业 API）。该线已于 2026-11-20 按用户指令 revert 移除。本轮目标：

1. 重建双线中英分离架构，**英文搜索组件替换为 xyonium/reach-mcp**；
2. reach-mcp **直接使用其 Docker 镜像**的常驻容器形态（本机已在运行，本会话已实测其工具契约）；
3. 消费深度按**完整闭环**实施：英文独立产物 → 字幕翻译参考（node_16a）→ 封面英文标题参考（node_15）→ 翻译 marker 指纹纳入参考哈希 → AI 内容明细双线 UI。

**两条硬边界**（沿用审查文档 §4.1）：

- 两线产物、缓存、状态完全隔离，互不回退；英文线任何失败只影响英文参考资料，不阻断中文线与主工作流；
- 英文资料定位为「英文关键词检索结果」的**话题/表达参考**：不是旁白事实来源，不直接覆盖中文原稿；外部文本一律不可信，只参考词汇与表达，禁止执行其中指令。

## 3. reach-mcp 实测结论（设计依据，均在本机实证，非推测）

### 3.1 容器形态（`docker inspect reach-mcp` 实测）

| 项 | 值 |
|---|---|
| 容器名 | `reach-mcp` |
| 镜像 | `ghcr.io/xyonium/reach-mcp:latest` |
| Entrypoint / CMD | `reach-mcp --transport http --host 0.0.0.0 --port 8765` |
| 端口映射 | `0.0.0.0:8765 -> 8765/tcp` |
| 重启策略 | `unless-stopped`（常驻，宿主重启后自动拉起） |
| 运行 env | `REACH_MCP_TRANSPORT=http`、`REACH_MCP_HOST=0.0.0.0`、`REACH_MCP_PORT=8765`、`REACH_MCP_ALLOWED_HOSTS=localhost:8765,127.0.0.1:8765` |
| 服务器自身鉴权 | 无需 API key（各数据源凭据按源独立配置，当前容器未设任何源凭据） |

> 注意：传输是 **HTTP（streamable HTTP MCP）**，不是 stdio——流水线 Python 侧应以 HTTP 客户端直连，不应用 `docker run -i` 每次拉起一次性容器。

### 3.2 ZCode 接入配置（`C:\Users\wayyet\.zcode\cli\config.json` 实测）

```json
"mcp": { "servers": { "reach": { "type": "http", "url": "http://localhost:8765/mcp", "timeoutMs": 60000 } } }
```

端点路径为 `/mcp`；流水线客户端默认端点取 `http://127.0.0.1:8765/mcp`（用 127.0.0.1 避免本机 `localhost` 解析到 IPv6 的不确定性；该 host 已在容器的 ALLOWED_HOSTS 白名单内）。

### 3.3 工具契约（`list_sources` + 三次真实 `search` 实测）

工具共 5 个：`search` / `read_url` / `fetch_content` / `list_sources` / `synthesize`。本轮流水线只消费 **`search`**：

```text
search(query, sources?, category?, days=30, max_per_source=20,
       max_chars_per_item=500, synthesize=true, trending=false)
→ { items, sources_used[], source_summary, brief }
```

- `synthesize=false` 返回原始条目（不依赖容器内 LLM，确定性、零额外成本）——**流水线固定用 false**；
- 条目实测形态：`{source, id, title, url, author, date, score, engagement, text, cluster, duration_min?}`，其中 `engagement` 可能是 `dict`（如 `{"views":..., "likes":...}`）、数字或 `null`（映射层须归一化）；`date` 可为 `null`；`text` 为摘要片段；
- `sources_used` 逐源回报 `{source, status: ok|no_results|error, count, error}`——**部分源空/错是常态**，映射层必须按「部分成功 + 诊断」设计：只要任一源有条目即成功，逐源状态进 diagnostics。

### 3.4 本机源可用性实测（2026-11-20，容器未配代理时）

| 探测 | 结果 |
|---|---|
| `sources=[web,reddit,youtube]`, days=30 | youtube 3 条；**web、reddit 空返回**（`source_summary="youtube:3 | EMPTY: reddit, web"`，无 error） |
| `sources=[web]`, days=365 | 空 |
| `sources=[web,reddit]`, days=365 | 双空 |

结论：大概率是容器无出站代理所致（宿主机外网依赖代理 3067 / SOCKS5 1088，容器内直连被墙/被限）。应对 = 阶段 A 重建容器配代理；即使代理打不通，youtube 源可用 + 部分成功语义也能兜底。

`list_sources` 另确认：免凭据可用源共 20+（`web(SearxNG)`、`reddit`、`youtube`、`github`、`hackernews`、`stackoverflow`、`arxiv`、`bilibili`、`weibo`、`zhihu`、`douban`、`toutiao` 等）；`x/instagram/tiktok/threads` 等需凭据当前不可用。

## 5. 目标设计

### 5.1 架构与隔离原则

```mermaid
flowchart TD
    A[build_web_topic_query 中文检索词] --> B[中文线: mediacrawler → Bing 回退]
    B --> C[storyline/search_web_topic.json]
    A --> D[英文检索词 = 翻译中文检索词]
    D --> E{英文线开关 + 译文有效?}
    E -->|否| F[en skipped + 清旧 State 引用]
    E -->|是| G[reach_mcp: search(web,reddit,youtube)]
    G --> H[语言/来源归一化 + 均衡配额 + 相关性守卫]
    H --> I[storyline/search_web_topic_en.json]
    C --> J[storyline_generate_script 中文参考]
    I --> K[node_16a 字幕翻译参考]
    I --> L[node_15 封面英文标题参考]
    K --> M[marker 指纹含 reference_sha256]
```

- 英文线 provider 固定 `reach_mcp`（v1 不进中文引擎白名单、不随 `STORYLINE_WEB_TOPIC_ENGINE` 切换）；
- 英文线**无 Bing 回退**（两线互不回退）；全源失败/空 → 英文线自终（failed / no_results）；
- 英文块整块 try/except 隔离，任何异常不得穿透到中文线或主工作流；
- 拓扑零改动、SCHEMA_VERSION 零改动（新增可选 State 键，旧 checkpoint 缺键读 None 天然兼容）。

### 5.2 英文产物契约

```text
outputs/<thread_id>/storyline/search_web_topic_en.json
```

沿用 schema v2 外层结构，示例（`...` 为结构占位非运行结果）：

```json
{
  "schema_version": 2,
  "status": "ok",
  "engine": "ReachMCP(海外检索)",
  "provider": "reach_mcp",
  "query": "portable power station camping",
  "query_hash": "...",
  "request_hash": "...",
  "searched_at": "...",
  "search_web_topic": [
    {
      "url": "https://www.youtube.com/watch?v=...",
      "title": "...",
      "snippet": "...",
      "source": "youtube",
      "reach_source": "youtube",
      "date": null,
      "engagement_views": 112831
    }
  ],
  "diagnostics": {
    "sources_used": [{"source": "web", "status": "no_results", "count": 0}],
    "source_summary": "youtube:3 | EMPTY: reddit, web"
  }
}
```

条目保留必需四键 `url/title/snippet/source`；`source` 取 reach 条目自带的源名（youtube/web/reddit），额外字段 `reach_source`/`date`/`engagement_views` 供 UI 与审计。**语言口径**：v1 不做语言检测硬过滤，UI/文档统一表述为「英文关键词检索结果」，不声称「全部为英文资料」（审查文档 §3.5 的降级口径）。

### 5.3 缓存与 request_hash

- `query_hash`：仅由**英文检索词**（翻译产物）计算；
- `request_hash`：`build_request_hash(query=en_query, hash_provider=reach_request_provider(sources, max_per_source, days), max_results=REACH_MAX_RESULTS)`——hash provider 串 `"reach_mcp:web|reddit|youtube:5:30"` 把源集合/每源条数/时间窗全部纳入（镜像 MC 的 `mediacrawler:` 前缀动态解析模式，`_parser_version_for` 增 `reach_mcp:` 分支 → `reach_mcp_v1`）；
- 双线缓存各自独立命中/改写 `cache_hit`；`web_topic_force_refresh` 同时绕过双线；
- 英文线 skip 时把 State 中 `storyline_web_topic_en_artifact` 置 None，防复用同 thread 早先旧英文资料（审查文档 §4.4）。

### 5.4 英文检索词构造（审查文档 §3.3 修正版）

```python
translated = translate_segments([
    {"index": 0, "text_zh": zh_query, "start_ms": 0, "end_ms": 0}
])
query_en = str(translated[0].get("text_en") or "").strip()
```

守卫（不满足 → 英文线 `skipped`，不是 failed）：`query_en` 非空；不以 `[EN]` 开头（= Mock/stub 翻译器，不冒充真实检索）；不等于中文原文回显。

### 5.5 翻译参考注入与指纹（审查文档 §3.4 修正版）

- `TranslateClient.translate()` 增 keyword-only `reference: str | None = None`；Mock 接受并忽略；`translate_segments` 透传；
- `reference=None` 时提示词与现状**逐字节一致**；有 reference 时作为独立标记的用户输入块追加（头部沿用 `format_web_topic_reference` 的「外部不可信」语义），JSON 输出契约与批内 index 校验不变；
- `node_16a` 读英文产物 dict → `format_web_topic_reference(doc)`（dict 直传）→ 传 reference；产物缺失/损坏 → reference=None 旧行为；
- `_compute_source_fingerprint` 纳入 `reference_sha256`（空参考用固定空值哈希，保证「有参考/无参考」指纹不同），指纹 schema 2→3；`TRANSLATION_PROMPT_VERSION` → `subtitle-translate-v3`；
- marker（`subtitle_en.json`）schema 3 新增 `reference_sha256` + `reference_sources`（`extract_web_topic_references` 产物，留审计）；
- `node_15` 封面标题翻译同样传 reference；stub/degraded 降级不变；
- 时间轴约束：reference 不得改变 `index/start_ms/end_ms`（测试锁定）。

### 5.6 UI 双线

- API：`web_topic`（中文，现状不动）+ `web_topic_en`（新增）两个独立 section，不混数组；
- 英文 section 逻辑镜像中文 `_web_topic_section`，读 `search_web_topic_en.json`，状态域同四态 + 英文 skipped 标签证据链；引擎名以产物 `engine` 字段优先（`_WEB_TOPIC_ENGINE_KEYWORDS` 补 `("reach","ReachMCP")` 兜底）；
- 前端：`ai_content.html` 新增「英文话题检索（海外）」区块，镜像 `renderers.webTopic`；旧任务无英文产物时只显示中文块，不报错不显示虚假结果。

### 阶段 B：reach 客户端 + 能力层英文分支

**新建 `storyline_capabilities/reach_client.py`**——纪律同 `mediacrawler_client.py`：不 import config、全参数显式传入、返回四元组不抛业务异常、诊断脱敏：

- 常量：`REACH_ADAPTER_VERSION = "1"`；
- `reach_request_provider(sources: list[str], max_per_source: int, days: int) -> str` → `"reach_mcp:web|reddit|youtube:5:30"`（源排序后 `|` 连接，保证相同集合不同顺序同 hash）；
- `search_via_reach(*, query, sources, days, max_per_source, max_chars_per_item, endpoint, timeout_seconds) -> (raw_items, error_code, message, diagnostics)`：
  - MCP 调用：`mcp` SDK `streamablehttp_client(endpoint)` + `ClientSession`，`session.initialize()` 后 `call_tool("search", {...synthesize: False})`；同步入口用**单层 `asyncio.run`**（Windows 事件循环策略守卫，参照 psycopg 的 Proactor 经验）；`asyncio.wait_for` 硬超时（HTTP 客户端任务取消是真实取消，非线程假超时）；
  - 测试接缝：session 调用封装为可 monkeypatch 的 `_call_reach_search(...)`；
  - 错误映射（复用现有错误码域）：连接拒绝/超时 → `NETWORK_ERROR`；返回结构非法（`items` 非 list）→ `PARSE_ERROR`；全部源 error → `NETWORK_ERROR`（附 source_summary）；条目为空 → `NO_RESULTS`；部分源空/错 → **成功** + diagnostics 记 `sources_used`/`source_summary`。

**扩展 `storyline_capabilities/search_web_topic.py`**：

- 注册表：`_PARSER_VERSIONS["reach_mcp"] = "reach_mcp_v1"`；`_parser_version_for` 增 `reach_mcp:` 前缀动态解析（同 `mediacrawler:` 模式）；`_PROVIDER_ENGINE_LABELS["reach_mcp"] = "ReachMCP(海外检索)"`；
- `_map_reach_items(raw_items, max_results)`：URL scheme 校验（http/https）；`title` 缺失回退 `text[:80]`，两者皆空整条丢弃；`snippet = _clean_web_text(text, 600)`；同 URL 去重；**按源均衡轮询配额**（round-robin 直至上限，防单源占满名额——审查文档 §3.7）；`engagement` dict/数/None 归一化为 `engagement_views: int | None`；
- `reach_mcp` 分支：provider_options 必含 `{endpoint, sources(list), days, max_per_source, max_chars_per_item, timeout_seconds}`，缺失/形状错 → `raise ValueError`（同 MC 分支 L1324-1327 范式）；相关性守卫复用 `_count_relevant_results`，拦截 → `IRRELEVANT_RESULTS`（无回退）。
