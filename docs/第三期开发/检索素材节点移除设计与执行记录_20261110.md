# 检索素材节点移除设计与执行记录(2026-11-10)

## 1. 背景与决策

用户在监控页「完整 LangGraph 工作流(mode=auto)」可视化中要求删除「检索素材」
(`storyline_search_media`)节点。该节点是 `storyline_load_media` 之后的可选
Pexels 旁路:环境变量 `STORYLINE_PEXELS_API_KEY` 已配才触发,按
`storyline_targets.query` 拉取外部图片/视频,产物整体覆盖
`storyline_media_artifact`。

**删除范围 = 彻底删除**(用户确认,与 2026-11-08 B1 ASR 移除先例同模式):
节点文件 + 能力文件 + 图接线 + 测试 + 活文档全部摘除;git 历史可随时找回。

## 2. 影响面盘点(删除前确认)

- **生产调用链唯一**:`storyline_capabilities/search_media.py` 的唯一生产调用方
  即 `nodes/storyline/node_search_media.py`;`storyline_capabilities/__init__.py`
  无 re-export。
- **`storyline_media_artifact` 不会变死字段**:writer 有两个
  (`node_load_media.py:61` 无条件主写、`node_search_media.py:55` 条件覆盖,
  `_last_wins` 取后者);删除 search_media 后回到单一来源。reader 三个
  (split_shots / understand_clips / `_common._read_media_list`)只认字段不认
  来源,零影响。
- **`storyline_search_media_artifact`(state.py)是现存死字段**:全仓库从无
  任何读写者(节点实际写的是 `storyline_media_artifact`);本次标 DEPRECATED
  墓碑(B1 模式:声明保留仅为旧 checkpoint 兼容)。
- **env 双名分裂随删除消失**:路由层读 `STORYLINE_PEXELS_API_KEY`
  (graph.py)、能力层读 `PEXELS_API_KEY`(capability);两者在 config.py /
  .env.example / 启动脚本中本就无条目,不会留下死配置文件。
- **无关同名**: `storyline/firered_adapter.py` 的 `search_media` ToolSpec 是
  FireRed 上游注册表(移植参考物,`OPTIONAL_TOOLS` 成员,无 import 方),不动;
  `web/node_map/workflow.json` 的 `search_media` 属旧 FireRed 14 节点静态描述
  数据,不属于 LangGraph 主图,不动。
- **拓扑角色**:search_media 有出边(→ split_shots),不是死胡同,故死胡同
  合成 END 计数(=2)不受影响。
