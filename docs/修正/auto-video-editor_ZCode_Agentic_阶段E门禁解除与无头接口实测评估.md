认证为 CLI 本机登录态（此前 `zcode login` 已完成）。工作目录为仓库外临时目录。

| # | 命令（要点） | 结果 | 关键证据 |
|---|---|---|---|

| 2 | `zcode --resume sess_288eb952… -p "我上一条消息让你回复的是哪两个字?…"` | exit 0 | 同 sessionId；`response:"正常"`（凭上文正确回答）；inputTokens 18286（增量=新 prompt）→ **上下文真实延续** |

## 3. 可行性结论（摘要，全文见设计文档附录 A.5）

**总体判定：可行**，可按 E-T4 预设的降级形态接入，但能力边界明确：

| 维度 | 结论 |
|---|---|
| 调用形态 | `zcode -p <prompt> --cwd <workspace> --mode <build\|plan\|guarded> --json` |
| 结果获取 | `--json` 结束时单块结构化结果（sessionId/turnId/response/usage）；**无流式结构化事件** |
| 流式 UI | 仅纯文本逐行（无结构）；`--json` 与流式互斥，v1 二选一 |
| 过程 trace | **不可用**（中途工具事件任何 `-p` 形态都不外发）→ `show_execution_trace` 在 zcode 链路固定降级为"状态+最终文本"，不得伪造（§6.3） |
| 会话映射 | `thread_id` ↔ `sess_*` 持久化，后续轮次 `--resume`（实测上下文延续正确） |
| 长 prompt | Windows argv 32767 字符硬上限 + stdin 不可用 → `max_prompt_chars` 默认 30000；超长上下文走 `--attach`（E-T1 验证） |
| 取消 | 必须管理真实 node PID 树或 Windows Job Object（实测教训 #4/#5） |
| 权限 | `-p` 默认 `--mode yolo` → 适配器必须显式传 `--mode`，禁止依赖默认值 |
| 成本 | 单次固定开销 ~18k input tokens（cacheRead 缓解）；短/畸形 prompt 也会触发自主工具探索（#6 实测 87k）→ 按轮记录 usage，权限模式显式指定 |
| 版本风险 | 接口未文档化，可能随升级变更 → 启动自检（`--version` + `--help` 含 `-p, --prompt`）+ 版本变化复测 + 自检失败禁用选项 |

## 5. 遗留风险与复测触发

1. **版本脆弱**：0.17.1 实测契约无官方承诺，升级即可能破坏 → 适配器启动自检
   （设计 §4.2 第二级前提 2），自检不过则 UI 禁用并给出明确原因。
2. **无授权声明**：账号额度策略、并发限制均为 Z.ai 单方掌握 → 上线前小流量验证，
   多租户场景按单账号共享额度评估。
3. **成本失控**：无每轮步数/预算旗标可设 → 适配器按轮记录 `usage`，异常放大时告警；
   后续 E-T1 探索 `--disallowed-tools` 收敛工具面。
4. **复测触发**：CLI 版本变化 → 重跑附录 A.5 契约表冒烟（约 6 次小调用）。
