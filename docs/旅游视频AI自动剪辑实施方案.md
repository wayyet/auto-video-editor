# 旅游视频 AI 自动剪辑实施方案

> 目标:手机拍摄的无人声旅游素材 → 自动剪辑 → 带解说配音 + 字幕 + BGM 的竖屏短视频(快手)
> 日期:2026-06-13

---

## 一、目标与约束

| 项目 | 确认结果 | 影响 |
|---|---|---|
| 成片规格 | 竖屏 9:16,1080×1920,30~60 秒 | 横拍素材需智能裁切/构图重排 |
| 硬件 | 无独立显卡 | 所有 AI 模型走云端 API,本地只跑 ffmpeg/Node/Python 等轻量工具 |
| 配音 | 商用 TTS API(火山引擎/阿里云/MiniMax 任选其一) | 需注册并提供 API Key |
| 工作方式 | 你提供「视频素材 + 主题 + 提示词」,我(Claude)负责分析与剪辑编排 | 素材放入 `kuaishou` 文件夹即可 |

---

## 二、总体架构

```
你的输入:视频文件 + 主题 + 提示词
        │
        ▼
① 素材预处理      ffmpeg + PySceneDetect:转码、场景切分、抽帧
        ▼
② AI 画面理解     视觉大模型逐镜头打标:内容、地点特征、画质、高光评分
        ▼
③ 脚本与剪辑决策   LLM 结合你的主题/提示词 → 解说文案 + 剪辑时间线(EDL)
        ▼
④ 配音与字幕      商用 TTS 生成解说 → 按时间戳生成 SRT/ASS 字幕
        ▼
⑤ BGM            media-downloader 下载免版权音乐 / 本地曲库 → 自动闪避(ducking)
        ▼
⑥ 渲染合成        ffmpeg(基础)或 Remotion + GSAP/Lottie(动画字幕、花字)
        ▼
成片:1080×1920 mp4 → 快手发布
```

## 三、工具选型结论(基于逐一调研)

### 核心采用

| 工具 | 角色 | 无 GPU 可用 |
|---|---|---|
| **ffmpeg** | 转码、裁切、拼接、混音、压字幕,整条流水线的发动机 | ✅ |
| **Claude(视觉大模型)** | 画面理解、文案生成、剪辑决策编排 | ✅ 云端 |
| **PySceneDetect** | 场景自动切分(开源,配合 ffmpeg) | ✅ |
| **商用 TTS API** | 解说配音(推荐火山引擎"豆包"音色或 MiniMax,中文旅游解说自然度高) | ✅ 云端 |
| **media-downloader** | Claude 技能,自动搜索下载免版权 BGM/补充空镜(Pexels/Pixabay/YouTube) | ✅ |
| **Remotion + GSAP/Lottie** | 进阶字幕动画、片头标题、地点花字(React 程序化渲染) | ✅ |

### 备选/特定场景采用

| 工具 | 调研结论 | 定位 |
|---|---|---|
| **FireRed-OpenStoryline**(小红书) | AI 剪辑 Agent:素材理解→脚本→BGM 卡点→对话式微调,官方 Demo 就含旅行 Vlog;支持 Claude Code 技能调用,AI 走 API 无需 GPU;Windows 可装,也有 Docker | **路线 B 主干**,效果上限最高的现成方案 |
| **short-video-factory** | Electron 桌面应用:提示词→文案→TTS→自动混剪+字幕,批量出片;但不做画面理解,只按文案随机混剪素材 | 快速量产备选,适合同一批素材出多条片 |
| **CutClaw**(GVCLab) | 多 Agent 把数小时素材按音乐节奏剪成卡点短片(编剧/剪辑/审片三 Agent) | 素材量大、想要纯音乐卡点风格时启用 |
| **video-spec-builder + HyperFrames** | 前者像导演一样追问需求产出逐镜头脚本 video-spec.md;后者用 HTML 渲染成片(擅长文字/版式/动画,不能生成实拍画面) | 做片头包装、文字动画类片段 |
| **Video Use**(browser-use) | Claude Code 技能:素材丢文件夹→对话→出 final.mp4 | 与路线 A 同思路,可作为技能直接安装 |
| **Pixelle-Video**(阿里) | 全自动短视频引擎,支持上传自有素材 AI 分析生成脚本,模型全走 API(DashScope/Kling 等) | 路线 B 的替代候选 |

### 暂不采用(及原因)

| 工具 | 原因 |
|---|---|
| **LTX-2** | 音视频生成大模型,本地推理需大显存 GPU,你无独显跑不动;后期如需 AI 转场/空镜,可走其云端 API,且成本较高 |
| **ViMax** | 定位是"从零生成视频"(导演+编剧+生成一体),与"剪辑自己拍的素材"目标不符 |
| **D3.js / Three.js / Canvas** | 数据图表/3D 场景库,旅游解说片用不上;留作日后特效扩展 |
| **HTML 版剪映(Open Design html-video)** | 浏览器手动剪辑器,与"全自动"目标冲突,仅作人工微调兜底 |
| **Claude Design** | 用于生成视觉主题/设计规范代码,做片头模板时再引入 |

## 四、三条实施路线

### 路线 A:Claude 直接编排(推荐起步,零部署)

就在当前 Cowork 环境完成,完全符合你设想的工作流:

1. 你把视频放进 `kuaishou` 文件夹,发给我主题和提示词;
2. 我用 ffmpeg + PySceneDetect 切分场景、抽帧;
3. 我直接"看"关键帧,理解每个镜头拍了什么,给出高光评分;
4. 按你的主题写解说文案,产出剪辑时间线;
5. 调商用 TTS 生成配音(需你提供 API Key),生成字幕;
6. media-downloader 配 BGM,ffmpeg 合成竖屏成片。

优点:今天就能开始,无任何安装;每一步可人工确认。
缺点:单条出片约 10~20 分钟交互时间,不适合无人值守批量。

### 路线 B:部署 FireRed-OpenStoryline(效果上限最高)

在你电脑安装(Python 3.11 + 配置 LLM/TTS API Key),通过 Web 界面或对话:

- 自动素材理解、脚本生成(支持用范文定义文案风格)、BGM 智能卡点、字体/音色推荐;
- 对话式微调:"第三段慢一点、换安静点的音乐";
- 可把满意的剪辑流程存成 Skill,换素材一键复刻 → 解决批量问题。

优点:专业级效果,旅行 Vlog 是其官方场景;缺点:首次安装配置约半天。

### 路线 C:short-video-factory(快速量产)

下载安装包即用:填 OpenAI 兼容 API + 选 TTS → 批量自动混剪。
适合"一批素材按不同文案出 N 条片"的矩阵玩法,但它不理解画面内容,镜头与解说的对应是随机的,质量上限低。

**建议:A 起步验证效果 → 满意后部署 B 做精品 → 需要矩阵量产再加 C。**

## 六、工作流约定(路线 A)

**你提供:**

1. 视频文件 → 放入 `kuaishou` 文件夹(建议每次一个子文件夹,如 `kuaishou/大理0613/`);
2. 主题提示词,建议模板:

```
地点:云南大理洱海
主题:一个人的治愈系旅行
风格:文艺、慢节奏 / 或:活泼种草风
成片时长:约 45 秒
解说人称:第一人称
必须保留的画面:日落那段
文案要求:结尾引导关注
```

3. 商用 TTS 的 API Key(火山引擎/阿里云/MiniMax 任一,首次提供即可)。

**我产出:**

- `分镜分析.md`(每个镜头的内容、评分、是否选用)→ 你确认
- `解说文案.txt` → 你确认后配音
- `成片_主题名.mp4`(1080×1920)+ `字幕.srt`

## 七、成本估算(单条 45 秒成片)

| 项目 | 估算 |
|---|---|
| 视觉分析 + 文案(LLM API) | 约 ¥0.1~0.5 |
| 商用 TTS(约 150 字解说) | 约 ¥0.01~0.1(各家均有免费额度) |
| BGM | 免费(免版权曲库) |
| 渲染 | 本地 ffmpeg,免费 |
| **合计** | **每条成片 < ¥1** |

LTX-2 等 AI 视频生成 API 每条转场约 ¥1~5,故仅按需启用。

## 八、风险与注意事项

1. **横拍素材竖屏化**:1080p 横拍裁竖屏会损失画质与构图,优先用手机竖拍;横拍素材采用"上下模糊填充"或智能跟踪裁切。
2. **BGM 版权**:快手发布务必用免版权音乐(Pexels/Pixabay)或快手曲库,避免下架。
3. **TTS 选型**:先用各家免费额度试听对比音色,再决定充值哪家。
4. **AGPL 许可**:short-video-factory 为 AGPL-3.0,个人使用无碍,二次开发商用需注意。
5. **素材管理**:原始素材保留备份,流水线只读不改原片。
