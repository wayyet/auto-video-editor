## 2. 根因

### 根因①(直接原因):期望的输出结构从未展示给模型

- schema 只经 `--output-schema` 临时文件传给 mcode 做**返回后校验**(`agent_gate/cli_client.py:331-334`),模型生成时不可见(模型 thinking 原话:"schema not visible / need infer");
- 翻译 system prompt(`jy_common/translate_client.py:52-60`)只说"只输出 JSON,不要输出其它文字",**没有任何输出结构示例**;lightweight 模式忽略 system 角色,提示词并入用户消息,内容照样没有结构;
- 用户消息只含输入 payload `{"segments":[...]}`,模型自然镜像输入键名 —— #1/#3 正是照抄 `segments`;
- 内层纠错提示只有一句校验错误文本 "data must have required property 'translations'",模型据此修对了顶层键(#2/#4),但条目形状仍在猜。
- 性质判定:4 次响应全部 HTTP 200,不是传输偶发,**不改代码重试大概率再失败**。

### 根因②(诊断盲区):报错误导 + trace 全链路无人消费

`TranslationError.trace`(结构:`ok/error/raw_head 4000字/parsed`,vlm_client.py:190-195)挂在异常对象上,但全仓库 grep 无任何消费方打印或落盘 —— console_run.log:225-315 只能看到最终兜底文案。同线程旁证:`storyline/script.json` 的 llm_trace 显示脚本生成任务里模型同样发生键名漂移(`narration/captions` 漂成 `raw_text`),该后端模型键名漂移是已知倾向(与 2026-11-14 filter/group 形状错配同族)。
