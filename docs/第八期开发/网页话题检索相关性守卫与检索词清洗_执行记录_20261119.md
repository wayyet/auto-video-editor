# 网页话题检索相关性守卫与检索词清洗 执行记录(2026-11-19)

## 1. 背景与根因定案

任务 `console-061cd2d39245`(海上清真寺 Vlog)的「网页话题检索」返回 10 条结果**全部**为
`ahu.edu.cn`(安徽大学教务处/教务系统/智慧安大),与检索词「海上清真寺旅游攻略,开放时间
(勿写平台名)、素材记录了一次阴天参访清真寺的过程。」零相关;垃圾结果随后经 `script.json`
references 注入文案生成并在 AI 内容明细页展示。

取证链(全部只读核查):

1. 产物 `diagnostics`:`http_status 200 / final_host www.bing.com / proxy_enabled true /
   response_bytes 114351 / parser bing_html_v1` —— 这是一次真实的 Bing 响应,解析器照单全收。
2. 全仓(含 .git 历史、tests、docs、diagnostics)搜 `ahu.edu.cn` / `智慧安大` 仅命中该任务
   的 3 个产物文件 —— 排除 fixture / 缓存污染 / 代码回退(引擎层本就无回退链)。
3. 缓存 key 含 `query_hash + request_hash`(provider+query+参数+语言+解析器+schema),且产物
   `status=ok` 非 `cache_hit` —— 排除别的任务结果串门。
4. 同日早间 video-001 同引擎同代理 10 条结果完全相关(日落主题);同检索词 + 同代理 + 同参数
   的请求在事后重放(实验 A)返回正常清真寺结果,直连(实验 B)与清洗后检索词(实验 C)也正常。
   代理出口实测为 Azure 新加坡数据中心(52.187.4.238, Microsoft Corporation)。

**根因**:Bing 对数据中心出口的**间歇性**反爬降级 —— 向被标记的共享出口 IP 返回整页无关的
降级/缓存 SERP(本次疑似为同一出口上其他用户的查询缓存);而解析层对「结果与检索词相关性」
零校验,垃圾以 `status=ok` 畅通流入下游。次因:检索词构造把写给文案模型的指令括号段
「(勿写平台名)」原样送进了搜索引擎。
